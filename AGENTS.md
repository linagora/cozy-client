# Agent rules — cozy-client

Instructions for any AI coding agent (Claude Code, Cursor, Copilot, Codex, Gemini,
opencode…) working in this repository. Read this before writing code.

This file is the **single source of truth**. Per-agent files (`CLAUDE.md`,
`.github/copilot-instructions.md`, `.cursor/rules/*.mdc`, `GEMINI.md`) only point back
here — do not duplicate content into them.

## Two levels of rules

1. **Generic Twake / Cozy conventions** (git, JavaScript/TypeScript, testing, cozy-client
   usage) live in **[linagora/twake-guidelines](https://github.com/linagora/twake-guidelines)**.
   - **Claude Code:** install the plugin — `/plugin install twake-guidelines@twake-guidelines`.
   - **Other agents:** read the central `AGENTS.md` in that repo.
2. **This repo's own decisions** are below. When they conflict with a generic convention,
   **this file wins for this repo**.

For setup, publishing and linking, see **[README.md](README.md)** and
**[docs/dev.md](docs/dev.md)** — not duplicated here.

## Decisions specific to this repo

### This is a library consumed by Twake / Cozy app

`cozy-client`, `cozy-pouch-link` and `cozy-stack-client` are published to npm and
imported by all web and mobile apps. Anything exported from `packages/*/src/index.js` is
public API.

- No breaking change without a `BREAKING CHANGE:` footer in the commit (lerna bumps a
  major from it).
- Prefer adding an option over changing a default.
- Check how [twake-drive](https://github.com/linagora/twake-drive) and the other apps
  use an API before changing its behaviour to ensure breaking changes.

### Source is JavaScript + JSDoc; types are generated, not written

Packages are written in `.js` with JSDoc, type-checked by `tsc` (`checkJs`) and the
`.d.ts` files under `packages/*/types/**` are **emitted from the JSDoc**. So:

- JSDoc is the type contract. Keep `@param`, `@returns` and `@typedef` accurate — a
  wrong JSDoc ships a wrong type to every app.
- Do not hand-edit anything under `packages/*/types/` or `docs/api/`.
- Do not introduce `.ts` source files.

### Generated docs and types are committed — CI fails if they drift

`docs/api/**` (typedoc) and `packages/*/types/**` (tsc) are committed and regenerated by
CI, which fails on any diff. Every code line added or removed in a documented file shifts
the `Defined in …:LINE` links, so "comment-only" changes drift too.

Before every push, from the repo root:

```bash
yarn docs          # regenerates docs/api/**
yarn types         # regenerates packages/*/types/**
```

Commit the regenerated output in the PR (a separate `docs:` commit is fine).
`yarn lint` + `yarn test` green does **not** mean the PR is ready.

### Performance is measured on every PR

CI runs `yarn bench` on the PR and on the base branch and posts a comparison comment.
The redux store reducers (`packages/cozy-client/src/store/**`) and the pouch-link
document normalisation (`normalizeDocs` in `packages/cozy-pouch-link`) are hot paths.

- Do not add per-document work in those paths without checking the benchmark output.
- If you change a hot path, add or extend a case in `packages/cozy-client/benchmarks/`.

### Offline is a first-class target

`cozy-pouch-link` gives apps offline reads and writes. A feature that works only against
`cozy-stack-client` is incomplete: check the pouch link path (and its limits documented
in `docs/offline/`) before calling a change done.

### Tooling

- Node 24 (`.nvmrc`), Yarn 4 through Corepack (`corepack enable`), Lerna workspaces.
- Commits follow Conventional Commits and are checked by commitlint (`cozy` config).
- Tests are Jest, colocated `*.spec.js` next to the source.

## Quick checklist before you open a PR

- Public API change → non-breaking, or `BREAKING CHANGE:` footer present.
- JSDoc updated to match the code.
- `yarn build && yarn test && yarn docs && yarn types` run; regenerated `docs/` and
  `packages/*/types/` committed.
- Hot-path change → benchmark checked, case added if needed.
- Offline (pouch link) path considered.
- Commit messages pass commitlint.

Generic Cozy / JS and git conventions are **not** repeated here — they live in
[twake-guidelines](https://github.com/linagora/twake-guidelines).
